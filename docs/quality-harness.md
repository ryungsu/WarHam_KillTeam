# 팩션·규칙 검수 하네스

## 실행

```sh
pnpm verify
# 패키지 관리자 없이 설치된 Node로 실행할 때
node scripts/verify.mjs
```

한 번 실행하면 단위 테스트 → 실제 데이터 품질 검사·실제 컴포넌트 서버 렌더링 → 타입 검사 → 빌드 → 오프라인 캐시 생성 순으로 진행한다. 실패 시 다음 단계로 넘어가지 않고 종료 코드 1을 반환한다. GitHub Actions도 같은 `pnpm verify`를 사용한다. 커밋·푸시·배포는 수행하지 않는다.

빠른 품질 검사만 실행하려면 `pnpm quality` 또는 `node scripts/quality/run.mjs`를 사용한다. 보고서는 Git에서 제외되는 `tmp/quality/report.json`에 생성되며 오류마다 팀·요원·프로필 ID와 검사 종류를 기록한다.

## 자동으로 막는 패턴

| 문제 | 검사 |
|---|---|
| Severe·Lim1·Hvy(Repos)·Rnd 같은 누락 | 등록된 모든 팀의 실제 무기 WR 토큰을 전수 순회, 태그 해석 및 본문 전체 문자열 링크 일치 검사 |
| 약어는 되지만 본문 링크가 없음 | 실제 RuleMarkdown 서버 렌더링에서 규칙 버튼 확인, 고정 회귀 예시와 데이터 기반 검사 병행 |
| Poison 설명이 다른 팀과 섞임 | 팀 범위 규칙 사전 사용, 플레이그 마린과 래버너의 Poison ID·설명 분리 검사 |
| 일부 요원만 옛 Toxic 문구 | 동일 팀의 공유 규칙 원문 일관성 검사 |
| 래버너 능력 탭이 비어 있음 | 화면이 사용하는 referenceAbilities 함수로 계약에 명시한 공통 규칙 노출 검사 |
| 데이터시트 능력 누락 | 실제 CompactDatasheet를 모든 요원에 대해 렌더링하고 표시된 능력 수 대조 |
| 한국어 누락 | 팀·요원 명칭 및 모든 능력·플로이·진영 장비의 번역 누락 검사 |
| 이미지 뒤바뀜 | 파일 존재, 카드 제목·페이지·헤더 좌표·검수 PNG 해시 검사 |
| 새 팀을 데이터에만 추가 | 팀 계약 미등록 시 실패, 편성 인원과 공통 규칙을 명시하도록 강제 |

기본 데이터 검사는 현재 7팀·55종·303개 키워드 사용 위치를 대상으로 하지만, 개수는 고정하지 않고 데이터에서 계산한다. 이미지 원문 대조 증거는 현재 신규 3팀 21종에 있다. 기존 팀의 옛 이미지까지 새로 검수했다고 간주하지 않는다.

## 하네스 자체 검증

실제 앱 데이터를 복제한 메모리에만 다음 오류를 주입한다: 규칙 삭제, 본문 링크 제거, 래버너 진영 플래그 제거, 공유 규칙 일부만 구문 변경, 번역 삭제, 챔피언/봄바디어 이미지 교환, 잘못된 카드 제목, 미검수 팀 추가. 각 오류를 해당 검사에서 탐지하지 못하면 하네스 자체가 실패한다. 실제 앱 데이터나 사용자 localStorage는 수정하지 않는다.

## PDF 이미지 재검증

```sh
python scripts/quality/verify_portraits.py --pdf-dir tmp/new-teams
```

`pypdf`·`Pillow`가 있는 Python이 필요하다. 공식 PDF 세 개는 plague-marines.pdf, nemesis-claw.pdf, raveners.pdf 이름으로 준비한다. 이 명령은 네트워크를 사용하지 않는다.

PDF 내부 Im 번호 순서를 믿지 않고 **제목 텍스트 좌표와 이미지 배치 좌표**로 공식 카드 헤더를 다시 찾는다. 그 결과의 제목·페이지·이미지 오브젝트가 기록과 같은지, 실제 PNG 픽셀이 그 이미지와 같은지 비교한다. PDF가 없거나 구조가 바뀌어 헤더가 모호하면 실패하며 임의로 다음 이미지로 넘어가지 않는다. 큰 PDF는 저장소·CI에 넣지 않아 이 검사는 기본 CI와 분리한다.

## 다음 팩션 추가 시

1. 공식 편성·무장·아키타입·능력 및 최신 날짜를 대조하고 출처를 기록한다.
2. 데이터·번역·무장 조합·편성 검증을 구현한다. scripts/quality/contracts.json에 팀 계약을 등록한다.
3. 공통 규칙의 진영 플래그와 요원별 능력을 분리한다. 팀별 동명 규칙을 전역 정의 하나로 합치지 않는다.
4. 카드 제목·좌표로 이미지를 추출하고 data-original/portrait-card-mapping.json에 원본·해시 증거를 추가한다. 신규 팀은 portraitProof=true로 등록한다.
5. 새 약어·본문 링크·특수 규칙은 필요한 회귀 예시를 추가한다. 미해결 키워드를 묵시적으로 건너뛰거나 포괄적인 예외 목록으로 숨기지 않는다.
6. `verify`와 PDF 이미지 검사를 통과시킨 뒤 실제 모바일 화면에서 선택·펼침·토스트·오프라인 동작을 확인한다.

## 검사의 한계

이 하네스는 자동 검수 가능한 누락·연결·일관성·이미지 교체 문제를 막는다. 브라우저 레이아웃·실제 터치·규칙 의미의 정확성·공식 최신 패치 전체 반영 여부를 자동 인증하지 않는다. 공식 새 버전으로 바뀌면 근거와 계약을 검토하고 갱신해야 한다. 이미지 해시를 갱신하는 것만으로 원문 검증을 대체해서는 안 된다.
